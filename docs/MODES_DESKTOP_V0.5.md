# V0.5.0 녹화 유형·다중 화면·일시정지 검증

## 두 녹화 유형

GUI 상단 **녹화 유형**에서 선택합니다. 마지막 선택은 개발 폴더의 `preferences.json`에
원자적으로 저장합니다. 개인 저장 경로가 있는 기존 `settings.json`은 변경하지 않습니다.
개인 preferences 파일은 Git에서 제외하고 `preferences.example.json`만 제공합니다.
설정이 손상된 경우 기존 파일을 보존하며 오류를 안내합니다. 대기 상태에서만 유형을 바꿀 수 있습니다.

| 항목 | 강의 녹화 | 일반 영상 녹화 |
|---|---|---|
| 사용 목적 | 필기/휴식 시간을 직접 제외 | 정지 화면·작업 대기 시간도 포함 |
| 원본 강의/동영상만 일시정지 | 녹화 계속. MyRecorder도 직접 일시정지해야 함 | 녹화 계속 |
| 화면이 그대로거나 시스템 소리가 무음 | 녹화 계속 | 녹화 계속 |
| MyRecorder 일시정지 | 화면과 오디오 함께 중단 | 화면과 오디오 함께 중단 |
| MyRecorder 재개 | 같은 세션의 다음 구간 시작 | 같은 세션의 다음 구간 시작 |
| 종료/저장 | 활성 구간만 최종 MP4 하나로 결합 | 활성 구간만 최종 MP4 하나로 결합 |

현재 두 유형의 캡처 엔진 동작은 같은 수동 방식입니다. 강의 모드는 사용 순서를 안내하고,
일반 모드는 원본의 정지 시간도 포함한다는 점을 안내합니다. `modes.py`의 별도 정책 객체가
명령 허용 상태와 안내를 관리하고, 추후 명시적 플레이어 어댑터를 연결할 확장 지점을 둡니다.
**재생 상태 자동 감지는 미지원**이며 GUI에도 표시합니다. 화면 정지/무음 감지로 자동 일시정지하지 않습니다.
드라이버/화면 캡처 오류에 대한 기존 안전 처리와 사용자의 수동 일시정지는 계속 유효합니다.

강의: 강의 재생 정지 → MyRecorder 일시정지 → 필기/휴식 → MyRecorder 재개 → 강의 재생.
사용자가 재개 버튼과 플레이어 재생을 누르는 사이의 대기 시간은 실제 캡처되므로 그만큼 포함됩니다.
자동으로 강의 재생 시점만 잘라내는 기능은 없습니다.

## 화면 범위 선택

- **선택 모니터 전체 / 영역 드래그 선택**: 기존 한 화면 선택입니다. 기존 화면 위 드래그 동작을 유지합니다.
- **두 화면에 걸친 영역**: 축소 모니터 배치도에서 드래그하거나 X/Y/너비/높이를 물리 픽셀로 입력합니다.
  배치도는 실제 영상 미리보기가 아닙니다. 화면을 가로지르는 영역은 이 버튼으로 선택합니다.
- **전체 가상 데스크톱**: 연결된 모든 모니터의 물리 영역을 포함하는 사각형 전체를 선택합니다.
  1920×1080 두 화면이 수평으로 붙어 있다면 일반적으로 3840×1080입니다.
  실제 원점은 주 화면 위치에 따라 음수일 수 있으므로 화면 좌표 진단 결과를 확인하세요.
- 데스크톱 영역은 대기 중 초록 테두리의 바깥쪽 조절점으로 크기를 바꾸거나 이름표로 이동할 수 있습니다.
  모니터 사이 내부 경계에는 전체 영역을 축소하는 조절점을 만들지 않습니다.
  좌표를 정확히 조정하려면 두 화면 영역 버튼을 다시 열어 수치를 입력할 수 있습니다.
- 녹화/일시정지/저장 중에는 영역과 유형을 잠급니다. 저장 성공 후 초록 상태로 돌아오며 영역을 유지합니다.
  제목과 다음 시작 버튼도 복원하고 동명 MP4에는 번호를 붙입니다.

### 좌표와 지원 범위

단일 화면에서는 기존 Qt 논리 좌표→물리 좌표 변환을 유지합니다.
데스크톱 선택에서는 **Windows 물리 가상 데스크톱 좌표**를 저장하고 FFmpeg desktop 캡처에 전달합니다.
모든 Qt 화면과 Windows 모니터를 식별자·원점·해상도·DPR로 검증하고 목록 순서에 의존하지 않습니다.
선택 이후 연결/배율/해상도가 바뀌면 이전 영역으로 시작하지 않고 재선택을 요구합니다.

혼합 DPI는 각 모니터 물리 교집합을 해당 QScreen의 논리 좌표로 따로 투영합니다.
모든 화면에 걸친 하나의 Qt 배율을 가정하지 않습니다. 음수 X/Y와 100/125/150%를 합성 검사했습니다.
실제 혼합 DPI의 gdigrab 좌표와 테두리 마우스 입력은 Windows 미검증입니다.
화면 사이 물리 빈 공간까지 포함한 사각형은 선택할 수 있으나 그 빈 부분의 출력은 Windows 캡처 결과에
따릅니다. 빈 공간만 있는 영역은 거부합니다. 디스플레이 복제/미러링처럼 대응이 모호한 배치는 지원하지 않습니다.

화면별로 독립된 테두리를 표시하고 각각 Windows 영상 제외 속성을 적용합니다.
하나라도 확인하지 못하면 캡처 중 전체 데스크톱 테두리를 숨깁니다. 빨강/주황 상태 표시는
영상 보호 정책상 실제 캡처 중 보이지 않을 수 있습니다. 최종 MP4에 선·라벨·조절점이 들어가지 않는지는
Windows에서 확인해야 합니다. 자체 오버레이 외의 창이나 콘텐츠 보호 기술을 조작하지 않습니다.

## 일시정지·싱크·PTS

기존 캡처/오디오 샘플 처리, 구간별 WAV 오프셋·resample·adelay 필터는 유지합니다.
일시정지에서 FFmpeg 및 오디오 자원을 닫고, 재개 시 새 세그먼트를 같은 세션에 기록합니다.
정지한 벽시계 시간은 세그먼트에 없으므로 최종 영상에서 제외됩니다.

결합 시 각 구간의 **영상 재생 길이**를 concat 타임라인에 지정합니다.
AAC 패딩이 포함될 수 있는 MP4 컨테이너 길이를 반복 누적하는 것을 피하기 위한 변경입니다.
각 결합 준비 구간과 최종 MP4의 패킷을 스트리밍 방식으로 읽어 PTS 시작/끝, DTS 역행,
최대 DTS 간격을 기록합니다. B프레임의 PTS 재정렬 자체는 오류로 취급하지 않습니다.
500ms 이상의 패킷 간격, 250ms 이상의 A/V 시작/끝 차이 등은 경고합니다.

로그는 기본 `F:\MyRecorder\Temp\session-...`에 있습니다.
`0000-pts.json` 등 구간 검사 결과와 `session.json`의 `timestamp_audit`를 확인할 수 있습니다.
최종 검사가 실패해도 이미 저장된 영상을 지우지 않고 경고하며 원본을 보존합니다.
PTS/길이가 맞아도 실제 발화·입 모양 싱크나 구간 경계 음질까지 보장하지 않습니다.
AAC 인코더 지연/패딩과 실제 오디오 드라이버 지연은 실기 검사 대상입니다.
패킷 검사는 저장 단계에서 실행하므로 긴 영상은 “저장 중” 시간이 늘어날 수 있습니다.

## 비정상 종료와 복구

MKV의 짧은 클러스터/flush, 구간 WAV, 원자적 세션 manifest와 실패 로그를 유지합니다.
정상 저장 이후에도 사용자가 완료 임시 세션 정리를 요청하기 전에는 원본을 지우지 않습니다.
Windows에서 실패 세션을 복사해 보존한 뒤 다음과 같이 복구를 시도할 수 있습니다.

```bat
".venv\Scripts\python.exe" -m myrecorder.cli recover "F:\MyRecorder\Temp\session-실제ID" --output "F:\MyRecorder\Recordings"
```

복구 결과는 `_복구` 이름으로 별도 저장합니다. 복구 도구는 WAV 헤더를 수정하므로 원본 세션을 먼저 복사하세요.
완전하지 않은 MKV, 시작 초기화 도중 종료한 구간, 손상된 저장 장치 및 4GB 초과 WAV는
자동 복구에 한계가 있습니다. 비정상 종료된 프로세스가 남아 있다면 먼저 종료 여부를 확인해야 합니다.

기존 제목/수동 OCR과 CLI 배속 변환을 유지합니다. 배속 변환 GUI는 이번 버전에 추가하지 않았습니다.

```bat
".venv\Scripts\python.exe" -m myrecorder.cli convert "F:\MyRecorder\Recordings\강의.mp4" --recorded-speed 2 --output-speed 1
```

## Linux에서 실제 수행한 검사

- unittest **127개**: 기존 113개 + 모드/환경 설정/데스크톱 좌표 10개 + 5회 일시정지 합성 미디어 1개 + 패킷 검사 오류 조건 3개.
- 기존 GUI/overlay/display/continuous/OCR smoke와 새 `modes_desktop_smoke.py`.
- 강의 모드 5회 일시정지/재개, 최종 저장 하나, 일반 모드 원본 정지/무음 이벤트 중 시계 증가,
  유형 잠금/재실행 복원은 Qt 모의 엔진으로 확인했습니다.
- 두 화면 영역 배치도, 실제 Qt 테두리 교집합/외곽 크기 조절, 125/150% 투영, 잘못된 화면 변경 차단을 검사했습니다.
  Win32 장치와 캡처는 모의입니다. offscreen 마스크/마우스 관련 경고가 있어 네이티브 입력 통과 판정은 아닙니다.
- 실제 FFmpeg로 6개 구간을 결합하여 MP4 하나, 길이 약 3.6초, A/V 차이 120ms 이내,
  구간·최종 PTS/DTS, 각 연결부 50ms 창에 시험음 존재, 디코딩 성공을 확인했습니다.
  합성 신호 시험이며 실제 WASAPI나 발화 음질 시험이 아닙니다.

## Windows 실기 재검증 — 전 항목 미검증

1. 먼저 기존 성공 조건에서 30초 화면+시스템 소리, 무음 녹화, F드라이브 MP4 저장을 확인합니다.
2. 강의 모드: 10초 녹화/5초 일시정지를 5회 반복하고 마지막 10초 뒤 저장합니다.
   최종 MP4 하나, 약 60초(실제 버튼 처리 지연에 따라 차이), 쉬는 25초 제외를 확인합니다.
   시작/각 재개 직후/끝에서 클랩·시각 패턴으로 싱크와 불필요한 무음을 확인합니다.
3. 일반 모드: 원본만 10초 정지하고 오디오도 무음으로 둡니다. MyRecorder 시계가 계속 증가하고
   그 정지 구간 10초가 최종 MP4에 남는지 확인합니다. 직접 MyRecorder 일시정지하면 제외되어야 합니다.
4. 각 모드에서 유형 변경 잠금/마지막 선택 복원, 빨강→주황→빨강→저장 중→초록을 확인합니다.
5. 모니터 1/2 각각 전체·부분, 두 화면 경계를 가로지르는 영역, 전체 가상 데스크톱을 차례로 녹화합니다.
   두 화면 100%에서 출력 원점/해상도/시각 기준점 일치와 선·라벨 제외를 확인합니다.
6. 주 화면이 오른쪽인 음수 X, 위쪽 보조 화면의 음수 Y, 100%+125%/150%에서 위 시험을 반복합니다.
7. 대기의 데스크톱 테두리 이동/외곽 크기 변경과 녹화 중 잠금, 숨김 선택 유지, 연속 3회 저장을 확인합니다.
8. 로그의 구간/최종 timestamp_audit, A/V 길이와 실제 발화 싱크를 함께 확인합니다.
   가능한 30분 및 1~3시간 시험에서 시작/중간/끝 오차를 기록합니다.
   목표는 절대 A/V 오차 200ms 이내, 시작 대비 변화 100ms 이내이며 아직 실기 달성 확인은 없습니다.
9. 중요한 영상 대신 시험 세션으로 비정상 종료/복구를 확인합니다. 원본 복사 후 복구 도구를 사용합니다.
10. 제목 인식·수동 OCR·동명 파일 보호·저장 실패 후 재시도·기존 CLI 변환의 회귀를 확인합니다.

## 안전한 업데이트

앱을 종료하고 기존 소스 폴더, `settings.json`, 있으면 `preferences.json`을 백업합니다.
GitHub **Code → Download ZIP**을 별도 폴더에서 풀고 내부 파일을 기존 개발 폴더에 덮어씁니다.
개인 설정 파일, `.venv`, `bin`, F드라이브 자료는 삭제하지 않습니다.
`install.bat` → `run.bat`으로 **V0.5.0**을 확인합니다. 새 외부 패키지는 없습니다.
EXE 사용자는 `build.bat`으로 다시 빌드해야 합니다. Windows EXE 빌드는 이 Linux 환경에서 미검증입니다.
