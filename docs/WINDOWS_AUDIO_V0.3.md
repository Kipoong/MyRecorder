# V0.3 Windows 11 오디오 재검증

## 확인된 사실과 수정 범위

사용자 V0.2 실기 보고: GUI 실행, 시스템 소리·마이크를 모두 해제한 화면 녹화,
MP4 생성·재생 성공. 시스템 소리 활성화 시 시작 0.5초 뒤 미수신 오류.
볼륨 설정만으로 캡처 실패를 단정할 수는 없습니다.
공개 문서와 테스트에는 실제 PC 장치 정보 대신 일반 설명과 가상 장치만 사용합니다.
개발 환경은 Linux. **V0.3의 실제 WASAPI 장치 탐지·데이터 수신·싱크·장시간 안정성은
Windows에서 아직 확인하지 않았습니다.** 아래 순서로 확인해야 합니다.

V0.2에는 '0.5초 내 frames == 0이면 오류'라는 성급한 조건이 있었습니다.
그 조건은 실제 장치 오류와 초기 지연/무음을 구분하지 못합니다. V0.3은 이를 제거했지만,
사용자 PC에서 데이터가 안 들어온 근본 원인까지 확정한 것은 아닙니다.

## 업데이트 (Python 소스 실행)

1. 앱을 종료합니다. 기존 프로젝트 폴더와 `settings.json`을 별도로 백업합니다.
2. GitHub `Code → Download ZIP`으로 최신 소스를 내려받아 압축을 풉니다.
3. 압축 해제된 `MyRecorder-main` 안의 소스·BAT·문서·테스트를 기존 개발 폴더에 덮어씁니다.
   폴더 전체를 중첩시키지 말고 `myrecorder\gui.py`가 기존 패키지 위치에 오게 하세요.
   ZIP에는 실제 `settings.json`이 없어 저장 경로 설정을 덮어쓰지 않습니다.
   기존 `.venv`, `bin\ffmpeg.exe`, `bin\ffprobe.exe`와 F드라이브 파일은 삭제하지 마세요.
4. `install.bat`을 실행한 뒤 `run.bat`을 실행합니다. 의존성은 V0.2와 동일하며
   PyAudioWPatch 0.2.12.7/Python 3.12 x64를 사용합니다. 가상환경을 지울 필요는 없습니다.
5. 제목 표시줄의 **MyRecorder V0.3**과 **시스템 출력 장치**, **오디오 장치 새로고침**을 확인합니다.
6. 예전 EXE는 소스 덮어쓰기로 갱신되지 않습니다. EXE 실행 사용자라면 `build.bat`으로
   새로 빌드하고 `dist\MyRecorder` 전체를 사용하세요. V0.3 EXE 빌드·실행은 미검증입니다.

기본 F:\MyRecorder\Recordings, Converted, Temp와 저장 경로 설정 방식은 유지합니다.
F드라이브 오류 시 경고하고 다른 폴더를 직접 고르게 하며 C드라이브로 자동 대체하지 않습니다.
모니터 배율 100% 제한과 기존 gdigrab/x264 화면 캡처 명령은 유지합니다.

## 먼저 장치 목록 확인

앱 시작 시 저장 경로 검사가 통과하면 비동기로 WASAPI 장치를 조회합니다.
장치를 연결/해제했다면 **오디오 장치 새로고침**을 누르세요.

- `Windows 기본 WASAPI 출력 장치 (자동)`은 매 녹화/재개 시 WASAPI 기본 출력 ID를 읽습니다.
  MME/DirectSound의 일반 기본 장치 ID로 대신하지 않습니다.
- Windows 소리 설정에서 확인한 기본 스피커 출력을 직접 선택하여 시험하세요.
  모니터 HDMI나 S/PDIF는 실제 그 장치로 소리가 나갈 때만 선택합니다.
- 목록에는 **출력 ID, Loopback 입력 ID, 입력 채널 수, 기본 샘플레이트**가 표시됩니다.
  호스트 API와 전체 장치 정보는 로그에 있습니다. 숫자 ID는 PC마다 다르므로 고정값을 쓰지 마세요.
- 선택 출력과 Loopback은 이름의 `[Loopback]` 접미사를 정리한 뒤 정확히 대응시킵니다.
  모호한 중복 이름은 임의로 연결하지 않고 오류를 냅니다. USB 등 연결 변경으로
  ID/이름이 달라지면 새로고침이 필요합니다. 앱 재실행 시 선택은 기본값으로 돌아갑니다.
- 목록은 PyAudioWPatch가 노출하는 WASAPI 출력들입니다. 대응 입력이 없으면
  `(Loopback 사용 불가)`와 함께 보이며 시작 시 명확한 오류가 납니다.
  영구 Windows endpoint GUID는 현재 라이브러리에서 사용하지 않습니다.

Windows 설정 → 시스템 → 소리의 출력 장치와 앱 볼륨 믹서에서 강의/브라우저 출력이
스피커인지 확인하세요. Windows 기본 스피커와 브라우저가 실제 쓰는 출력이 다를 수 있습니다.
시험 중 장치를 바꾸거나 분리하지 마세요.

## 상태별 해석

| 상태/코드 | 의미와 동작 |
|---|---|
| WAITING | 첫 데이터 대기. 초기 지연만으로 녹화를 중단하지 않음 |
| SILENT | 실제 PCM은 들어오지만 최근 샘플이 모두 0. 무음과 미수신을 구분 |
| RECEIVING | PCM 수신. 비영(非零) 데이터도 확인됐지만 실제 내용·품질은 청취 필요 |
| NO_DATA_TIMEOUT | 8초 이상 데이터가 없음. 무음/잘못된 출력/드라이버 원인을 단정하지 않고 경고하며 영상 녹화는 계속 |
| OUTPUT_NOT_FOUND / DEVICE_DISCOVERY_FAILED | WASAPI 기본 출력 또는 장치 목록 탐지 실패 |
| LOOPBACK_NOT_FOUND / LOOPBACK_AMBIGUOUS | 대응 Loopback 누락 또는 이름 중복. 임의 대체 안 함 |
| DEVICE_INIT_TIMEOUT / DEVICE_CONTROL_TIMEOUT | 장치 초기화/제어 호출 시간 초과. 드라이버와 로그 확인 |
| DEVICE_CHANGED | 선택한 ID의 이름이 변경됨. 새로고침 필요 |
| FORMAT_UNSUPPORTED | PCM16 기본/48000/44100Hz 및 원래 채널/최대2채널/모노 조합이 모두 지원되지 않음 |
| DEVICE_OPEN_FAILED / DEVICE_START_FAILED | 장치 열기/시작 실패. 드라이버·사용 중·독점 모드 확인 |
| STREAM_STOPPED / STREAM_STATUS_FAILED | 실행 중 스트림 중단 또는 상태 조회 실패 |
| BUFFER_WARNING | PortAudio 상태 플래그 존재. 데이터는 보존하되 누락 가능성 안내 |
| BUFFER_OVERFLOW / AUDIO_WRITE_FAILED | 쓰기 큐 초과/디스크 쓰기 오류. 녹화를 일시정지하고 임시 파일 보존 |
| DIAGNOSTICS_WRITE_FAILED | 진단 로그 쓰기 실패. 저장 장치·여유 공간 확인 |

무수신은 무음으로 확정하지 않습니다. 실제 오류 시에는 영상도 안전하게 일시정지하거나
시작을 취소하고 로그·세션을 보존합니다. 시작 실패 후에는 장치 선택과 재시도가 가능합니다.
계속 무수신인 채 종료하면 영상과 무음 트랙이 저장될 수 있고, **오디오 미수신 경고**가 뜹니다.
이를 오디오 녹음 성공으로 취급하지 마세요.

## GUI 테스트 순서

1. 시스템 소리·마이크를 둘 다 끄고 30초 화면 녹화. MP4 생성·재생이 이전처럼 되는지 확인.
2. 시스템 소리만 켜고 기본 자동 장치로 녹화. 스피커에서 테스트 음원을 재생하며
   WAITING에서 RECEIVING 또는 SILENT로 바뀌는지 확인. 30초 뒤 종료하고 실제 청취.
3. Windows에서 확인한 기본 스피커 출력을 직접 선택하고 2번 반복.
   장치 로그의 output.name과 loopback.name, input_device_index, rate/channels를 확인.
4. 소리를 끈 상태에서 먼저 시작하고 10초 뒤 음원을 재생. 초기 무수신으로 즉시 종료되지
   않는지, 수신 후 상태가 바뀌는지, MP4의 소리 시작 위치가 실제 재생 시점과 맞는지 확인.
5. 녹화 중 5초 재생 → 10초 무음 → 5초 재생. 중간 무음이 압축되어 뒤 소리가 앞당겨지지
   않는지 확인. PortAudio가 전달하는 타임스탬프와 실제 결과를 비교.
6. 일시정지/재개 5회. 재개 직후 장치 매핑·패킷 수신, 음성 중복·누락·싱크 확인.
7. 시스템+마이크 동시 녹음. 각각 들리는지, clipping/에코가 있는지 확인. 헤드폰 권장.
8. 시작/끝에 손뼉 또는 화면-소리가 함께 변하는 테스트 패턴을 넣어 A/V 오차를 기록.
   30분, 이후 1~3시간 시험. 목표: 절대 오차 200ms 이내, 시작 대비 오차 변화 100ms 이내.
   아직 이 기준 달성을 입증하지 못했습니다.
9. 여건이 되면 스피커/HDMI/S/PDIF 각각 실제 출력과 GUI 선택을 맞춰 시험.
   사용하지 않는 S/PDIF에서 데이터가 없다는 결과만으로 캡처 구현 실패라 단정하지 마세요.
10. 장치 접근 실패 후 무음 녹화로 다시 시작해 정상 동작을 확인. 임시 파일 보존도 확인.

## GUI 없는 오디오 진단

프로젝트 폴더에서 CMD로 실행합니다. 영상은 만들지 않으며 설정의 Temp 아래에
`audio-test-임의ID` 폴더와 로그, 선택적으로 시험 WAV를 생성합니다.

```bat
.venv\Scripts\python.exe -m myrecorder.audio
.venv\Scripts\python.exe -m myrecorder.audio --seconds 15
```

첫 명령은 출력/Loopback ID 목록을 보여줍니다. 두 번째는 기본 출력에서 15초간 녹음하며
매초 상태·callback 수·수신 프레임·무음 패딩 프레임·비영 데이터 수를 출력합니다.
음원은 사용자가 직접 재생하세요. 장치를 직접 지정하려면 목록에서 확인한 출력 ID를 사용합니다.
아래 `실제출력ID`를 숫자로 바꿔 실행하세요.

```bat
.venv\Scripts\python.exe -m myrecorder.audio --seconds 15 --output-device-id 실제출력ID
```

출력에는 실제 로그와 WAV 경로가 나옵니다. WAV를 플레이어로 청취하세요.
종료 코드 0: 목록 조회 또는 비영 PCM 수신(청취 검증 아님), 2: 무수신/무음 등 소리 확인 불가,
1: 장치/진단 실행 오류. 실제 소리 누락과 무음을 구별하려면 당시 음원을 재생했는지도 기록하세요.

## 로그와 재현 정보

- 장치 조회: Temp\audio-devices-임의ID.jsonl
- 녹화 세션: Temp\session-임의ID\audio-diagnostics.jsonl
- 독립 시험: Temp\audio-test-임의ID\audio-diagnostics.jsonl 및 system.wav
- 기존 FFmpeg 로그·MKV·WAV·session.json도 그대로 보존.

로그는 Windows/Python/PortAudio 버전, 전체 장치 사전, WASAPI 호스트·기본 출력,
선택 쌍, 포맷 지원 검사, 실제 열기 설정, 수신 상태·프레임 수·패딩 수·오류를 JSONL로 기록합니다.
로그에는 장치 이름과 PC 경로가 포함될 수 있으므로 공개 저장소에 커밋하지 않습니다.
문제 재보고 시 로그를 확인하고 민감한 이름/경로는 가린 뒤 전달하세요.
진단 로그는 상태 변화 시 기록되며 매 PCM 패킷을 디스크에 로깅하지 않습니다.

## 싱크 구현과 한계

FFmpeg 시작 단조 시각과 오디오 스트림 시작 단조 시각 차이를 세션 offset으로 저장합니다.
첫 PCM은 PortAudio의 input_buffer_adc_time/current_time 차이가 유효하면 콜백 지연을 보정하고,
이후 ADC 간격으로 시간 위치를 유지합니다. 잘못된/누락된 시각은 단조 시각과 샘플 길이로 대체.
WASAPI 네이티브 리소스는 생성부터 종료까지 트랙별 같은 전용 제어 스레드에서 처리합니다.
수신 공백은 쓰기 스레드가 무음으로 채워 압축하지 않으며, 콜백은 디스크 I/O 대신 제한된 큐 사용.
무수신 중에도 500ms 여유를 두고 무음을 점진적으로 기록해 종료 시 큰 패딩 작업을 줄입니다.

이는 FFmpeg의 실제 첫 프레임 타임스탬프를 공통 하드웨어 시계로 직접 받는 방식이 아닙니다.
50ms 이내 콜백 흔들림은 샘플 연속성을 우선하고 큰 시각 이상은 대체 시각을 사용합니다.
드라이버 지연이 크거나 ADC 시각이 불안정하면 오차/음성 잘림 가능성이 있습니다.
장시간 장치 시계 드리프트와 영상/음성 정밀 싱크는 실기 측정이 필요합니다.
단순 시간 길이 검사나 Linux 모의 테스트만으로 싱크 정확도를 보장하지 않습니다.

## 근거와 개발 검증

PyAudioWPatch는 출력 장치의 Loopback 대응물을 **입력 장치**로 노출합니다.
기존 헬퍼의 부분문자열 매칭 대신 접미사 정리 후 정확한 이름과 WASAPI 호스트를 확인합니다.
기본 출력 이름을 특정 사용자 장치로 하드코딩하지 않습니다.

- PyAudioWPatch 문서/콜백 예제: https://github.com/s0d3s/PyAudioWPatch
- Microsoft Loopback Recording: https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording

Linux 개발 검증: unittest 38개와 Qt offscreen GUI smoke 통과.
모의 장치의 기본/수동 매핑, 중복·누락·ID 변경, 포맷 대체, 열기 실패, 지연 후 수신,
무음 PCM/무수신 구별, 버퍼·파일 쓰기 오류, ADC 지연/공백 처리, 무음 영상 경로,
실패 로그·매니페스트 보존, 일시정지 메타데이터 보존, 합성 MP4 결합/변환 확인.
GUI는 장치 목록·선택 전달·초기화 실패 후 재시도와 저장 경로 유지 확인.
실제 Windows 장치, 화면·시스템 소리 수신, 실제 싱크, BAT·EXE·장시간 테스트는 미실시.
