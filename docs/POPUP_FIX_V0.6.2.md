# V0.6.2 — 확장 연결의 Invalid URL 수정

## 원인 확인

V0.6.1 팝업은 `chrome.tabs.query({active:true,currentWindow:true})`의 결과에서
`tab.url`이 항상 있다고 가정하고 `new URL(tab.url)`을 호출했습니다.
탭 메타데이터 주소가 없는 경우 같은 `Failed to construct 'URL': Invalid URL` 오류를
실제 Linux Chromium 확장 팝업에서 재현했습니다. 토큰 형식 확인 이후이며 **인증 저장/서버 통신 이전** 단계입니다.
토큰을 새로 발급하는 것만으로 이 주소 처리 오류가 수정되지는 않습니다.
사용자 Windows의 원시 Tab 객체는 수집하지 않았으므로 주소가 빠진 정확한 권한/창 상황까지 단정하지 않습니다.

## 변경 내용

- `tabs` 권한을 명시하여 현재 열린 탭의 제목·주소를 읽습니다. 연결할 탭을 확장 목록에서 확인/선택합니다.
  사이트 내용 접근은 기존처럼 선택 사이트의 별도 허용을 요구합니다.
  열린 탭 메타데이터는 목록 표시에 사용하며 외부 서버로 전송하지 않습니다.
- 확장 자체 화면·새 탭·브라우저 내부 페이지에서는 다른 강의를 임의로 선택하지 않습니다.
  열린 HTTP/HTTPS 강의 탭을 목록에서 직접 고를 수 있습니다.
- 주소 없음/잘못된 주소/내부 페이지/닫힌 탭을 구분하고 한국어 조치를 표시합니다.
- 연결 직전에 선택 탭 주소를 다시 검사합니다. 선택 후 다른 문서로 이동하면 목록 새로고침을 요구합니다.
- 권한 요청을 연결 버튼의 사용자 클릭에서 먼저 실행하고, 중복 클릭을 막습니다.
- 백그라운드의 sender URL도 검사합니다. 탭 제목/사이트는 표시하되 오류에 원시 비밀 URL을 그대로 붙이지 않습니다.
- 암호화 저장·재연결·요청/응답 서명과 녹화 엔진은 유지합니다.

## 지금 적용할 순서

1. 앱을 종료하고 기존 개발 폴더에 최신 ZIP 내부 파일을 덮어씁니다.
   개인 `settings.json`, `preferences.json`, `.venv`, `bin`, F드라이브 자료를 유지합니다.
   기존 설치가 정상이면 `run.bat`만 실행하면 됩니다. install.bat 재실행은 필요 없습니다.
2. Chrome `chrome://extensions` 또는 Edge `edge://extensions`에서 MyRecorder 확장을 새로고침합니다.
   확장 버전 **0.6.2**와 새 탭 정보 조회 권한을 확인/허용합니다. 권한 변경으로 비활성화되었다면 다시 켭니다.
   확장을 삭제할 필요는 없습니다. 같은 폴더를 유지해야 기존 확장 ID가 보존됩니다.
3. 이미 노출되었거나 새 발급을 원하는 인증 정보는 재사용하지 않습니다.
   앱 대기 상태에서 **연결 초기화**, 확장 팝업에서 **저장한 연결 삭제**를 수행합니다.
   새 인증 정보는 이 대화나 공개 저장소로 보내지 마세요.
4. 테스트 플레이어가 종료되었다면 개발 폴더 명령창에서 다시 실행합니다.

   ```bat
   ".venv\Scripts\python.exe" -m myrecorder.player_demo
   ```

   출력된 실제 `http://127.0.0.1:포트/index.html`을 브라우저의 일반 탭으로 엽니다.
   포트는 고정값이 아니며, 명령창은 열어 둡니다. 이전에 열려 있던 강의 페이지는 새로고침합니다.
5. 앱에 확장 ID를 입력하고 **로컬 연결 시작**을 눌러 새 연결 정보를 만듭니다.
6. 확장 팝업에 새 JSON 정보를 붙여넣고, 새로 추가된 **강의/테스트 영상 탭 목록**에서
   실제 테스트 영상 탭을 선택합니다. 표시되는 제목/사이트를 확인하고 **선택한 강의 탭 연결**을 누릅니다.
7. 연결 저장 완료 후 앱에서 video를 선택하고 자동 감지를 켭니다. 준비 완료 후 시험 플레이어의
   **강의 재생 (JS play)** / 일시정지로 5회 이상 확인합니다.

다음 실행부터는 저장한 연결을 사용하므로 토큰을 매번 다시 입력하지 않습니다.
처음 방문하는 사이트에는 최초 사이트 허용이 필요합니다.
재연결만으로 녹화는 시작되지 않습니다. 자동 연동 지원 범위/누락 가능성은 V0.6 안내를 유지합니다.

## 검증과 한계

- Linux unittest **159개 통과**: 기존 153개와 실제 공유 JS 주소 검사기의 6개 검사.
  새 검사에는 개발 환경의 Node가 필요하며, 프로그램 실행에 Node를 설치할 필요는 없습니다.
- 실제 Chromium **팝업 UI에서** 탭 선택 → 사이트 권한 요청 → 연결 정보 저장 → 스크립트 주입 →
  서명된 로컬 연결을 검증했습니다. 저장된 연결의 토큰 재입력 없는 흐름도 확인했습니다.
- 주소 메타데이터 없음, 자체 확장 화면, 선택 후 주소 변경, 닫힌 탭을 검사했습니다.
  기존 재생 자동 연동·브라우저/앱 서버 재시작 및 Qt 회귀 검사를 유지했습니다.
- 캡처/WASAPI/MP4/저장/DPI/자동 녹화 정책 파일은 V0.6.1과 동일합니다.
- **사용자 Windows의 Chrome/Edge 권한 승인, 실제 탭 연결 및 녹화 회귀는 미검증입니다.**
  팝업 시험은 Linux Chromium이며 기존 브라우저 시험의 녹화 엔진은 모의입니다.

아직 실패하면 새 팝업의 오류 문구와 대상 탭 종류(테스트 HTTP 페이지/실제 강의/iframe 등)를 확인합니다.
화면을 공유할 때 연결 JSON 영역과 개인 강의 URL은 가리고 오류 문구만 공유하세요.
