# V0.6.3 — 연결 정보 저장과 강의 탭 연결을 분리

## 이번 보고에서 확인한 것

V0.6.2의 “처음 한 번 앱 연결 정보를 입력하세요”는 입력값이 없고 확장 저장소에도
인증 정보가 없다고 응답할 때 표시됩니다. 유효한 JSON을 실제로 저장한 요청이 완료되었는지는
이 문구만으로 확인할 수 없었습니다. 사용자 PC의 저장소나 원시 이벤트는 수집하지 않았으므로
저장 실패의 구체적인 원인까지 확정하지 않습니다.

기존 코드에서는 저장이 사이트 권한 요청 뒤에 실행됐습니다. JSON을 붙여넣은 뒤 팝업을 닫고
다시 열면 입력이 사라져 같은 문구가 나오는 경우를 실제 Chromium에서 재현했습니다.
이 조건이 사용자 상황이라고 단정하지 않습니다. 반복 초기화 대신 각 단계를 따로 검증하도록 바꿨습니다.

## 새 화면에서 할 일

1. 앱을 종료하고 최신 ZIP 내부 파일을 기존 폴더에 덮어씁니다.
   개인 설정, `.venv`, `bin`, F드라이브 자료는 유지합니다. 기존 설치는 **run.bat만 실행**합니다.
2. 확장 관리 화면에서 MyRecorder 확장을 새로고침하고 강의 페이지도 새로고침합니다.
   앱과 확장 모두 **V0.6.3**인지 확인하세요. EXE를 사용한다면 다시 빌드해야 합니다.
3. 앱의 새 **연결 JSON 복사** 버튼을 눌러 현재 연결 정보를 복사하고 확장 입력칸에 붙여넣습니다.
   자동 복원되어 JSON이 숨겨져 있어도 이 버튼으로 복사할 수 있습니다. 초기화/재발급은 필요 없습니다. JSON 파일이 실제로 있다면
   **JSON 파일 불러오기**로 본문을 읽을 수 있습니다. 파일 이름/경로만 붙여넣지는 마세요.
   기존 앱 JSON이 유효하면 재발급하거나 초기화할 필요가 없습니다.
4. 새 버튼 **① 앱 연결 저장·확인**을 누릅니다.
   “암호화 저장·다시 읽기 확인 완료”와 **“앱 응답 정상”**이 나와야 합니다.
   입력만 하고 팝업을 닫으면 저장되지 않습니다. ①을 완료한 이후에는 닫아도 보관됩니다.
5. 아래 목록에서 테스트 영상/강의 탭을 고르고 **② 강의 탭 연결**을 누릅니다.
6. 앱의 video 목록에서 대상을 확인하고 자동 감지를 켭니다. 연결 확인만으로 녹화가 시작되지는 않습니다.

사이트 권한 요청은 ① 저장이 끝난 뒤 ②에서 실행합니다. 팝업이 권한 요청 중 닫히더라도
이미 저장한 인증 정보를 잃지 않습니다. 다음에는 저장한 정보로 앱 응답을 확인하므로 토큰을 다시 넣지 않습니다.

## 단계별 오류 코드

| 코드 | 의미·조치 |
|---|---|
| INPUT_EMPTY | 입력칸/저장소가 비어 있음. JSON 본문을 넣고 ①을 누름 |
| INPUT_JSON | JSON 형식 오류. 파일 이름이나 경로가 아닌 본문인지 확인 |
| INPUT_SCHEMA | port 숫자·64자리 token 형태가 맞지 않음. 앱 JSON 전체를 복사 |
| STORE_WRITE_FAILED | 브라우저 암호화 저장 또는 다시 읽기 실패. 브라우저 프로필/저장 권한 확인 |
| STORE_READ_FAILED | 기존 저장 정보를 읽지 못함. 저장소/프로필 문제 확인 |
| STORE_NOT_CONFIRMED | 저장 요청 뒤 인증 정보가 확인되지 않음. 코드만 공유해 추가 점검 가능 |
| AUTH_REJECTED | 앱이 인증 거부. 확장 ID와 현재 앱의 JSON 일치 여부 확인. 새 JSON으로 ①만 다시 가능 |
| APP_UNREACHABLE | 앱/포트에 연결되지 않음. 앱 실행 후 빈 입력칸으로 ①을 다시 누름. 저장 정보는 보존 |
| APP_UPDATE_REQUIRED | 앱도 V0.6.3으로 갱신해야 함. 이전 EXE 실행 여부 확인 |
| APP_PROOF_INVALID | 앱 응답 서명 확인 실패. 연결 포트/앱 상태 확인 |
| BACKGROUND_TIMEOUT | 확장 응답이 10초 안에 오지 않음. 저장소/확장 상태 확인. 인증 정보는 자동 삭제하지 않음 |
| BACKGROUND_UNAVAILABLE / BACKGROUND_REPLY | 확장 백그라운드 응답 문제. 확장 새로고침/버전 확인 |
| TAB_CLOSED / TAB_CHANGED | 대상 탭이 닫히거나 이동함. 탭 목록 새로고침 후 재선택 |

오류 화면에는 코드/단계/연결 포트만 표시하고 토큰 본문을 출력하지 않습니다.
문의할 때 JSON 영역은 가리고 **오류 코드와 문구만** 공유하세요. 토큰이나 인증 파일은 필요하지 않습니다.

## 내부 변경

- 입력 JSON의 형식을 별도 모듈에서 검사하고, 입력 완료와 저장 완료를 구분합니다.
- 브라우저 저장 뒤 메모리 캐시를 비우고 암호문을 다시 읽어 복호화가 되는지 확인합니다.
- 녹화 이벤트와 분리된 인증된 ping으로 실제 앱의 서명된 응답을 확인합니다.
  ping은 강의 소스/이벤트를 생성하거나 녹화를 켜지 않습니다.
- 앱 연결 확인이 끝난 경우에만 ②를 활성화합니다. 새 JSON을 입력하면 이전 확인 상태를 해제합니다.
- 앱 연결 실패만으로 기존 인증 정보를 삭제하지 않습니다.
- 캡처·WASAPI·MP4·싱크·저장 경로·자동 녹화 정책·듀얼 모니터 구현은 유지합니다.

## 검증과 한계

- Linux unittest **165개 통과**: 기존 159개와 JSON 입력 검사 5개/부작용 없는 ping 검사 1개.
- 실제 Chromium 팝업에서 붙여넣기 후 미저장 종료, 명시적 저장 후 재열기,
  JSON 파일 불러오기, 저장소 다시 읽기, 앱 서명 응답 확인을 검사했습니다.
- 저장 실패는 테스트에서 주입한 모의 오류이며 실제 Windows 저장 장애 재현은 아닙니다.
  실제 앱 서버 중지/재시작과 잘못된 인증 정보도 각각 분리된 코드로 확인했습니다.
  모의 백그라운드 무응답에서 10초 후 오류 표시와 재시도 복구도 검사했습니다.
- 기존 실제 팝업/브라우저 자동 연동/브라우저 재시작과 Qt 회귀 검사를 유지합니다.
- **Windows Chrome/Edge 저장소·DPAPI·실제 녹화는 미검증입니다.**
  이번 수정이 사용자의 실제 원인을 모두 해결했다고 단정하지 않으며, 실패 시 위 코드로 단계를 식별합니다.
