# V0.6.0 HTML5 강의 자동 연동 — 최소 기능 구현

## 지원 범위와 내용 보존 정책

Chrome/Edge Manifest V3 확장과 독립 `AutoLink` 상태 관리 모듈을 추가했습니다.
기존 화면 캡처/오디오/MP4/싱크/복구 모듈은 바꾸지 않았습니다.

- 강의 모드에서 선택한 **한 탭·한 문서·한 video**만 제어합니다. 다른 탭으로 포커스를 옮겨도 대상은 바뀌지 않습니다.
- 자동 감지 ON 시 먼저 짧은 실제 영상·시스템 소리 준비 구간을 같은 세션에 녹화한 뒤 자동 일시정지합니다.
- 지원되는 JavaScript `video.play()` 호출은 원래 재생을 보류합니다. 앱이 기존 엔진으로 시작/재개하고
  선행 시간(기본 0.5초)을 더 녹화한 뒤 ready ACK를 보내면 원래 play를 호출합니다.
- 플레이어 pause 이벤트 후 정지 여유(기본 1초, 0~3초 조절)를 더 녹화한 뒤 화면·오디오를 함께 일시정지합니다.
  그 전에 재생 요청이 오면 예정된 일시정지를 취소합니다.
- 재개할 때도 같은 세션의 새 구간을 열고 ready를 기다립니다. 최종 MP4는 하나입니다.
  시작/연결부에 정지 화면과 주변 소리, 대략 1~2초 이상의 여유가 포함될 수 있습니다.
  엔진 초기화/종료 시간에 따라 더 길어질 수 있으며 정밀 중복 제거는 구현하지 않았습니다.
- **순환 프리롤/소급 버퍼는 구현하지 않았습니다.** 선행 구간은 기존 엔진이 실제로 녹화한 영상과 오디오이며
  동일한 캡처 시간 기준을 씁니다. 게이트를 우회해 이미 재생된 내용을 복구하는 버퍼는 아닙니다.
- 기존 엔진은 일시정지 시 장치를 닫습니다. 준비 시험 이후에도 재개할 때 다시 시작 시간이 필요하므로
  매번 ready를 다시 기다립니다. ready는 스트림/프로세스 시작 확인이지 실제 오디오 패킷 수신·무손실 보장이 아닙니다.

**0ms, 무조건 누락 없음, 모든 플랫폼 지원을 보장하지 않습니다.**
가장 안전한 사용 순서는 자동 감지 ON → 준비 완료/주황 대기 확인 → 지원 플레이어의 재생 버튼입니다.
이미 재생 중인 탭에서 켜면 이전 내용은 복구하지 못하고 경고합니다.

### 게이트와 관찰 방식의 차이

| 플레이어 | 동작과 한계 |
|---|---|
| 최상위 문서 HTML5 video, 패치 후 JS play 호출 | play Promise를 보류하고 ready 후 재생. Linux 실제 Chromium 시험 범위 |
| 브라우저 기본 video 컨트롤, 주입 전에 캐시한 play, 별도 재생 구현 | JS 래퍼를 우회할 수 있음. playing 이벤트 뒤 자동 시작/재개하는 **관찰 방식**. 첫 부분 누락 가능 |
| iframe 내부 video, 닫힌 Shadow DOM video, canvas/전용 앱 플레이어 | 이 버전 자동 감지 미지원. 최상위 video 없음/감지 불가 표시 |
| EME/mediaKeys/encrypted 보호 영상 | 자동 연동 중지/미지원. 보호 기술을 우회하거나 키/복호화 데이터를 읽지 않음 |
| waiting/stalled 네트워크 버퍼링 | 녹화 유지. 화면 정지/무음 분석은 사용하지 않음 |
| 사이트가 자체 JavaScript로 video.pause() 호출 | HTML5 pause로 감지됨. 표준 이벤트만으로 인간 클릭과 사이트 스크립트의 의도를 완전히 구별할 수 없음 |

브라우저 자동 재생 정책, 사이트가 play 래퍼를 교체하는 경우, 커스텀 플레이어 제한은 남습니다.
ready 후 원래 play가 거부되면 자동 연동을 해제하고 현재 녹화를 유지하여 수동 확인을 안내합니다.
페이지 알림의 “관찰 방식”이면 내용 보존이 중요한 녹화에서는 먼저 MyRecorder 수동 녹화를 시작하세요.
사이트별 전용 어댑터, 순환 A/V 버퍼와 정밀 경계 편집은 다음 단계입니다.

## Windows 설치·연결

앱/확장을 사용자가 직접 설치·연결해야 합니다. 브라우저 스토어 배포나 Native Messaging 등록은 없습니다.

1. 앱을 종료하고 기존 소스, `settings.json`, `preferences.json`을 백업합니다.
   GitHub Code → Download ZIP 내부 파일을 기존 개발 폴더에 덮어씁니다.
   `.venv`, `bin`, 개인 설정과 F드라이브 자료는 유지합니다. `install.bat` → `run.bat`, **V0.6.0** 확인.
   새 런타임 패키지는 없습니다. EXE 사용자는 build.bat으로 다시 빌드하고 확장 폴더도 따로 유지합니다.
2. Chrome `chrome://extensions` 또는 Edge `edge://extensions` → 개발자 모드 → **압축해제된 확장 프로그램 로드**.
   개발 폴더 안 `browser_extension`을 선택합니다. 관리 정책이 설치를 막으면 우회하지 말고 수동 녹화를 사용하세요.
3. 확장 팝업에 보이는 **확장 ID**를 MyRecorder의 확장 ID 입력란에 붙여넣고 **로컬 연결 시작**을 누릅니다.
4. 앱에 표시된 JSON 연결 정보(port/token)를 복사하여 확장 팝업에 붙여넣습니다.
   강의 탭을 활성화한 상태에서 확장의 **현재 강의 탭 연결**을 누르고 그 사이트 접근 권한을 허용합니다.
   토큰은 비밀번호처럼 취급하며 화면 공유·저장소·문제 보고에 올리지 마세요.
5. 앱 목록에서 정확한 강의 제목·사이트·video 번호를 선택합니다. 여러 video가 있으면 광고/미리보기를 고르지 마세요.
   제목 입력과 영역/오디오 설정을 마친 뒤 강의 모드에서 **강의 재생 자동 감지**를 켭니다.
6. 준비 녹화가 끝나 주황 대기와 “준비 완료”가 보이면 플레이어의 재생/일시정지 버튼만 조작합니다.
   매 재개마다 녹화가 준비되는 동안 재생이 잠시 기다릴 수 있습니다.
7. 종료 때 자동 저장하려면 ON 전에 **강의 종료 시 MP4 자동 저장**을 선택합니다.
   기본 OFF이면 ended 후 여유 녹화→일시정지이며, 최종 저장은 MyRecorder 종료 버튼으로 합니다.

연결 정보는 앱을 다시 실행할 때 바뀝니다. 확장은 토큰을 신뢰된 확장 세션 저장소에만 보관합니다.
한 앱 연결은 하나의 확장 ID를 허용합니다. Chrome/Edge ID가 다르면 해당 ID로 앱을 다시 연결하세요.
ID를 잘못 입력해 연결한 경우 앱 종료/재실행 후 올바른 ID를 입력합니다.

확장 업데이트 시 확장 관리 화면의 새로고침을 누르고 강의 페이지도 새로고침한 뒤 다시 연결/대상 선택하세요.
기존 페이지에 남아 있는 이전 play 래퍼를 제거하기 위한 절차입니다. 새로고침/문서 이동으로 문서 ID가 바뀌면
기존 자동 연결을 이어 붙이지 않습니다. 현재 세션을 저장하고 새 문서를 선택하여 다시 켜세요.

## 예외·수동 우선권

- MyRecorder에서 직접 일시정지하면 **수동 일시정지 우선** 상태입니다. 브라우저 재생 요청으로 자동 재개하지 않습니다.
  게이트가 재생을 막을 수 있으므로 MyRecorder에서 직접 재개하거나 자동 감지를 해제하세요.
- 자동 감지 OFF는 현재 녹화를 종료하지 않습니다. 수동 시작/일시정지/재개/저장을 유지합니다.
- 사용자 종료는 자동 연동을 해제합니다. 저장 완료 후 초록 영역과 제목 편집/다음 시작을 복원합니다.
  다음 강의는 다시 대상 확인 후 ON 합니다. 일반 영상 모드에는 자동 연동을 적용하지 않습니다.
- 선택한 문서의 소식이 8초 이상 없거나 재생/장치 전환에 실패하면 감지 불가/연결 끊김을 표시합니다.
  **현재 녹화는 임의로 멈추지 않습니다.** 사용자가 수동으로 확인해야 합니다.
- 백그라운드 탭 타이머 제한, 절전 탭, MV3 서비스 워커 재시작도 끊김을 일으킬 수 있습니다.
  녹화 탭의 절전/백그라운드 동작은 Windows 브라우저에서 별도 시험해야 합니다.
- 연결 없이 플레이어 play 요청을 보류한 경우 35~40초 내 실패시키고 재생을 허용하지 않습니다.
  확장에서 연동을 해제하고 페이지를 새로고침하면 래퍼 없이 수동 재생할 수 있습니다.
- 자동 감지를 다시 켜는 설정은 대기 상태에서만 허용합니다. 연결 장애가 난 세션은 수동으로 마무리/저장한 뒤 재연결하세요.

## 보안과 독립 구조

`browser_bridge.py`는 127.0.0.1의 임의 포트에만 바인딩합니다. 256비트 실행별 토큰, 허용한 확장 ID,
Host/경로/JSON 크기/이벤트 순서를 검사합니다. Origin이 있으면 정확한 확장 Origin이어야 합니다.
확장 background fetch가 Origin을 생략하는 경우에도 토큰과 명시적 확장 ID 헤더를 요구합니다.
일반 웹페이지의 다른 Origin은 유효 토큰이 있어도 거부합니다. 토큰 없는 조회에 탭 목록을 공개하지 않습니다.
CORS를 모든 사이트에 열지 않으며, 브라우저 확장의 selected-tab/frame/document 식별을 사용합니다.

확장 비밀은 페이지 MAIN/ISOLATED 스크립트로 넘기지 않습니다. DOM 게이트 채널은 비밀 인증 경계가 아닙니다.
선택된 페이지 자체가 재생 구현을 바꾸거나 DOM 알림을 조작하는 것을 완전히 방어하는 기술은 아닙니다.
중요한 인증 경계는 확장 background와 로컬 앱 사이입니다. 연결/이벤트/소스 수와 본문 크기는 제한합니다.

HTTP 스레드는 캡처를 호출하지 않고 제한된 큐에 이벤트를 넣습니다.
GUI 타이머에서 `AutoLink`가 수동 우선권·꼬리 시간·선행 시간·ready·끊김 정책을 판단한 뒤
기존 start/pause/stop 작업을 호출합니다. Recorder/오디오/MP4 내부 인자는 수정하지 않았습니다.

## 지연 진단

기본 `F:\MyRecorder\Temp\auto-link-<ID>.jsonl`:

- browser_event: 브라우저 사건 시각, 앱 수신 시각, 차이, media_time, gate/observer 구분
- auto_dispatch: 앱이 시작·재개·정지를 요청한 monotonic 시각
- capture_started: 기존 Recorder의 실제 시작 기준 시각, GUI 준비 시각과 오디오 상태
- capture_paused: 실제 정지 요청 기준 시각
- ready_ack: 준비 요청부터 ACK까지의 앱 측 경과 시간
- recorder_state / auto_disabled / manual_command: 상태 전환과 끊김·수동 우선권

wall-clock 전송 차이는 OS 시계 보정 영향을 받습니다. 앱 내부 경과 시간은 monotonic 기준입니다.
playing의 media_time은 이벤트 관찰값이지 실제 MP4 첫 프레임/첫 음성 누락량의 직접 측정값은 아닙니다.
테스트 영상의 시계/시작 플래시·오디오와 MP4를 비교해야 합니다. 토큰은 진단 로그에 쓰지 않습니다.
탭 제목/로컬 경로는 개인 정보일 수 있으므로 로그는 공개 저장소에 올리지 않습니다.

## 보호 없는 로컬 시험 플레이어

개발 폴더에서 명령 프롬프트로 실행합니다. 기존 FFmpeg와 설정의 Temp를 사용합니다.

```bat
".venv\Scripts\python.exe" -m myrecorder.player_demo
```

출력된 localhost 주소를 Chrome/Edge에서 엽니다. 합성 60초 영상·음성과 HTML은 Temp에 생성합니다.
앱에 강의 탭을 연결하고 준비 완료 후 **강의 재생 (JS play)** / **강의 일시정지**를 조작합니다.
화면의 시계·시작 플래시와 MP4 첫 부분을 비교하세요. 기본 video 컨트롤 표시 버튼은 관찰 방식 시험용입니다.
기본 컨트롤 경로가 게이트를 우회하는지는 브라우저 구현에 따라 달라집니다. 종료는 명령창 Ctrl+C입니다.

## 검증 결과와 한계

- Linux unittest **143개 통과**: 기존 127개와 자동 정책/실제 loopback 인증·출처·본문·재전송 검사 16개.
- 기존 GUI/overlay/display/continuous/modes_desktop/OCR와 새 auto_gui smoke 통과.
  Qt 모의 녹화 엔진으로 준비 구간, 5회 재개, 수동 우선권, ended 자동 저장, MP4 하나,
  초록 복귀와 토큰 없는 지연 로그를 검사했습니다. 이 MP4는 시험용 모의 파일입니다.
- **실제 Linux Chromium + 압축해제 확장 + HTML5 WebM + 실제 로컬 HTTP** 시험 통과.
  5회 ready 후 재생/정지, waiting 무시, 다른 탭 격리, 캐시된 play 우회 시 관찰 경고,
  연결 끊김 때 수동 유지. 녹화 상태 전환은 모의이며 Windows 캡처/오디오를 연결한 시험은 아닙니다.
- 기존 실제 FFmpeg 6구간 결합·PTS/A-V·파일 보호 검사를 유지합니다.
- 로컬 데모의 60초 A/V 생성과 HTML 제공을 Linux에서 확인했습니다.
- Windows Chrome/Edge 설치·권한/자동 재생 제약·플랫폼별 지원·실제 싱크·듀얼 모니터·EXE는 미검증입니다.

선택적 개발 브라우저 검사에는 Playwright와 별도 시험 Chromium이 필요합니다.
프로그램 사용자 requirements에는 추가하지 않았습니다.

```sh
PYTHONPATH=. python -m unittest discover -s tests -v
QT_QPA_PLATFORM=offscreen PYTHONPATH=. python tests/auto_gui_smoke.py
# Playwright/시험 Chromium을 개발용으로 별도 설치한 환경에서만:
PYTHONPATH=. python tests/browser_auto_smoke.py
```

## Windows 실사용 재검증 — 미검증

1. 먼저 사용자 확인 조건인 모니터 1의 화면+시스템 소리+MP4+실제 싱크를 수동으로 재검증합니다.
2. 로컬 시험 플레이어에서 준비 완료 후 재생합니다. 앱/브라우저 로그의 ready→playing 순서와
