# V0.6.4 — BACKGROUND_REPLY 및 팝업 출처 검사 수정

## 확인한 코드 경로

V0.6.3의 `[BACKGROUND_REPLY]`는 팝업이 백그라운드에서 유효한 응답을 받지 못했을 때의 표시입니다.
이전 백그라운드는 `sender.url === chrome.runtime.getURL('popup.html')`라는 문자 단위 완전 일치를
만족하지 못하면 UI 요청에 응답하지 않고 종료했습니다.

실제 Linux Chromium에서 같은 팝업을 `popup.html?context=diagnostic`으로 열자
동일한 BACKGROUND_REPLY를 재현했습니다. 같은 패키지 팝업이어도 주소 매개변수/fragment가
붙으면 거부되던 경로를 수정했습니다. **사용자 Windows에 실제로 매개변수가 붙었는지,
파일/워커 버전이 섞였는지는 아직 확인하지 않았으며 원인을 단정하지 않습니다.**

## 변경 사항

- 팝업→백그라운드 UI 전용 Port를 추가하고 요청 ID별 응답과 오류를 명시적으로 반환합니다.
  플레이어 이벤트 전송 채널과 분리합니다.
- 저장 명령 전에 **ui_hello**로 실제 백그라운드 코드 빌드와 manifest 버전을 확인합니다.
  버전이 다르면 인증 정보를 보내기 전에 차단합니다.
- 같은 확장 protocol/host의 `/popup.html`만 허용하고 매개변수/fragment는 출처 판정에서 제외합니다.
  URL 없이 확장 Origin만 제공하는 팝업은 탭이 없는 신뢰 컨텍스트에 한해 처리합니다.
  웹페이지 콘텐츠 스크립트나 다른 확장 ID, 다른 문서 경로에는 저장소 권한을 주지 않습니다.
- 허용되지 않는 UI 요청은 묵살하지 않고 `UI_SENDER_REJECTED`로 응답합니다.
- 채널 종료/응답 형식 오류/백그라운드 버전 불일치를 각각 구분합니다.
  이미 닫힌 채널은 다음 작업 전에 재연결하고 버전을 다시 확인합니다.
- 초기화, 토큰 변경, DPAPI 파일 삭제는 이 문제의 해결 절차에 포함하지 않습니다.
  기존 암호화 저장, 앱 서명 통신, 녹화 엔진은 유지합니다.

## 사용자가 적용할 순서

1. 이번 오류 수정은 확장 쪽입니다. **기존 앱 V0.6.3을 그대로 사용할 수 있습니다.**
   최신 ZIP을 별도 폴더에서 풀고 `browser_extension` 폴더의 내용을 기존 같은 폴더에 **전체** 덮어씁니다.
   새 `popup_rpc.js`, `ui_sender.js`가 포함되어야 합니다. 폴더 위치는 바꾸지 마세요.
   앱 설정/가상환경/F드라이브 자료를 수정하거나 install.bat을 실행할 필요는 없습니다.
   전체 소스도 업데이트한다면 개인 설정, `.venv`, `bin`을 유지합니다.
2. 열려 있는 이전 확장 팝업/확장 자체 탭을 닫습니다.
3. Chrome `chrome://extensions` 또는 Edge `edge://extensions`에서 MyRecorder 확장을 새로고침합니다.
   **확장 버전 0.6.4**를 확인합니다. 확장 삭제/새 폴더로 재등록은 필요하지 않습니다.
4. 브라우저 확장 아이콘으로 팝업을 다시 엽니다.
   상단에 **백그라운드 0.6.4 응답 확인 · UI 채널 정상**이 나와야 합니다.
   이 확인 전에는 JSON을 반복 붙여넣거나 새 토큰을 만들지 마세요.
5. 앱이 이미 V0.6.3으로 실행 중이면 그대로 사용합니다. 새로 실행할 때는 run.bat만 사용합니다.
   앱의 **연결 JSON 복사** → 확장에 붙여넣기 →
   **① 앱 연결 저장·확인** → 앱 응답 정상 후 **② 강의 탭 연결** 순서입니다.
   저장한 정보가 이미 있다면 빈 입력칸으로 ①에서 확인할 수 있습니다.

확장 자체 화면을 별도 탭으로 열어 사용하더라도 같은 확장의 popup.html이면 처리합니다.
다만 새로고침 전에 열어 둔 옛 팝업은 닫고 다시 열어야 합니다.
V0.6.3 EXE를 사용 중이라면 이번 확장 수정만을 위해 다시 빌드할 필요는 없습니다.

## 새 진단 표시

| 코드 | 의미 |
|---|---|
| UI_CHANNEL_CLOSED | UI 채널 종료/구버전 워커/수신부 없음. 확장 전체 파일과 새로고침 확인 |
| UI_VERSION_MISMATCH | 팝업·백그라운드 실제 코드·manifest 버전 불일치. 토큰 전송 전에 차단 |
| UI_SENDER_REJECTED | 팝업 출처 검증 실패. 확장 아이콘으로 팝업을 다시 열기 |
| UI_BAD_REPLY | 요청과 맞지 않는 응답 형식 |
| BACKGROUND_TIMEOUT | UI 요청 후 10초간 응답 없음 |

기존 INPUT_EMPTY, STORE_WRITE_FAILED, AUTH_REJECTED, APP_UNREACHABLE 등 저장/앱 확인 코드는 유지합니다.
오류 보고에는 상단 **백그라운드 상태 문구와 오류 코드만** 있으면 됩니다.
토큰, JSON, 실제 강의 전체 URL은 보내지 마세요.

## 검증

- Linux unittest **171개 통과**: 기존 165개와 팝업 출처 검사 6개.
- 실제 Chromium에서 V0.6.3 매개변수 팝업의 무응답을 재현했습니다.
- V0.6.4의 매개변수/fragment 팝업으로 버전 확인→암호화 저장→앱 확인을 통과했습니다.
- 실제 콘텐츠 스크립트가 UI Port로 인증 정보 삭제를 요청했을 때 거부하고 저장 정보를 유지했습니다.
- 혼합 워커 버전은 모의 응답을 주입해 인증 정보 전송 전에 차단하는지 검사했습니다.
- UI 채널을 종료시킨 뒤 재연결하는 경로, 기존 팝업·페어링·자동 연동·재시작·Qt 검사를 수행했습니다.
- **Windows Chrome/Edge의 실제 sender 정보와 저장/녹화는 미검증입니다.**
  사용자 기기에서 해결 완료라고 단정하지 않습니다. 재발 시 새 상태 코드로 실패 단계를 구분합니다.
