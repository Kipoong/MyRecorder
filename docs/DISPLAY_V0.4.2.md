# V0.4.2 디스플레이 대응 수정 및 Windows 재검증

## 확인된 호출 경로와 아직 확인되지 않은 원인

V0.4.1은 `Window.start()` → `physical_region()` → Windows 모니터 이름과
`QScreen.name()`의 casefold 완전 일치 후보 수 검사 순으로 진행합니다.
후보가 정확히 하나가 아니면 보고된 “Qt 화면과 Windows 모니터를 정확히 대응시키지 못했습니다”
예외를 발생시킵니다. 이 분기는 선택 영역의 모니터 경계 검사 **이전**입니다.
영역 선택/테두리 미리보기에서는 그 예외를 숨겼기 때문에 선택은 성공한 것처럼 보이고
녹화 시작에서만 실패할 수 있었습니다. 화면 목록 순서를 직접 연결하던 코드라는 의미는 아닙니다.
실제 장치 이름·원시 좌표 로그는 아직 받지 못했으므로 구체적인 이름 불일치 원인은 확정하지 않습니다.

사용자의 최종 확인 조건은 Windows 11 확장 듀얼 모니터, 좌우 1920×1080 두 화면,
두 화면 모두 100%입니다. 앞서 전달된 단일 모니터 조건은 정정되었습니다.
주 모니터는 아직 특정하지 않았고 Windows 화면 번호와 앱 목록 번호가 같다고 가정하지 않습니다.

## 변경한 대응 규칙

- `EnumDisplayMonitors`로 연결된 모든 모니터를 수집합니다. `GetMonitorInfoW`의 장치 이름,
  HMONITOR, 주 모니터 플래그, 가상 데스크톱 영역을 기록합니다.
- `EnumDisplaySettingsExW`의 현재 모드에서 물리 원점과 해상도를 별도로 조회합니다.
  필요한 필드나 API 조회가 실패하면 임의 좌표로 대체하지 않고 중단합니다.
- `EnumDisplayDevicesW`의 모니터 장치 ID/설명과 `GetDpiForMonitor`의 DPI를 진단에 기록합니다.
  이 DPI API는 호출 프로세스 인식 상태의 영향을 받으므로 로그의 runtime DPI 상태와 함께 봐야 합니다.
  매칭에는 Qt DPR과 실제 물리 모드 크기의 일치도 별도로 확인합니다.
- Qt 전체 화면의 이름, 논리 좌표, 크기, DPR, 논리 DPI, 주 화면 여부를 기록합니다.
- 표준 `\\.\DISPLAYn` / `DISPLAYn` 이름 접두사를 정규화합니다. 고유 식별자가 맞더라도
  원점/크기가 모순되면 중단합니다. 이름이 달라도 **원점·DPR·크기 조합이 양쪽 목록에서
  유일하게 대응할 때만** 매칭합니다. 동일 해상도만으로 고르거나 첫 화면으로 대체하지 않습니다.
- Qt/Windows 목록 순서와 표시 번호는 매칭에 사용하지 않습니다. 선택 콤보에는 실제 QScreen
  객체를 보관하고 선택 시 이름·좌표·DPR을 고정합니다. 녹화 직전 다시 검증하며,
  선택 이후 레이아웃이 바뀌면 재선택을 요구합니다.
- 좌표 변환은 `물리 원점 + (선택 좌표 − Qt 원점) × 모니터 내부 배율`입니다.
  가상 데스크톱 전체 원점에 DPR을 곱하지 않습니다. 왼쪽/위쪽 보조 모니터의 음수 좌표를 유지합니다.
  반올림된 Qt 화면 크기를 위해 크기 비교에는 최대 2물리 px, 원점 비교에는 1px 허용오차를 둡니다.
- 한 화면 내부 부분 영역과 해당 화면 전체를 지원 대상으로 합니다. **두 화면을 가로지르는 녹화는
  지원하지 않습니다.** 경계 밖 시작 좌표는 오류입니다. 마우스 드래그 선택은 화면 안으로 제한합니다.
- 테두리 장식/조절점의 외곽 좌표 대신 선택 영역 자체만 변환합니다. 기존 테두리 이동/크기 조절,
  상태 색, 영상 제외 실패 시 숨김 정책은 유지합니다. 녹화/일시정지 중 영역은 계속 고정됩니다.

## DPI 초기화와 경고

공식 진입점 `launcher.py` / `python -m myrecorder`는 Qt를 가져오기 전에 DPI를 준비합니다.
이미 확정된 프로세스/스레드 DPI를 보존하며 Qt Windows 플랫폼에도 동일 모드를 요청합니다.
아직 unaware라면 PMv2 설정을 한 번만 시도하고, 접근 거부 시 반복 호출하지 않습니다.
프로세스/스레드 인식 모드가 다르거나 지원하지 않는 상태라면 시작을 중단합니다.

Qt 6.8 Windows 플랫폼 소스는 요청 모드가 현재 모드와 같을 때 setter 호출을 생략합니다.
이 동작을 근거로 설정했지만 실제 설치된 PySide6 버전에서 경고가 사라지는지는 Windows 검증 대상입니다.
경고를 숨기거나 모든 실패를 배율 문제로 취급하지 않습니다.
100%의 이미 고정된 DPI 모드는 물리 크기가 일치하면 사용할 수 있고,
100%가 아닌 화면은 모니터별 인식이 아니면 중단합니다.

참고: https://doc.qt.io/qt-6/highdpi.html 및 Qt 6.8의
`src/plugins/platforms/windows/qwindowscontext.cpp`, `qwindowsintegration.cpp`.

## 진단 로그 확인

1. `run.bat` 실행 후 화면 목록에서 대상 화면을 고르고 **선택 모니터 전체** 또는 **영역 드래그 선택**을 누릅니다.
2. **화면 좌표 진단** 버튼을 누릅니다. 대응 결과와 로그 경로를 표시합니다.
3. 시작 직전에는 `operation=recording_start` 이벤트를 항상 남깁니다.
   미리보기는 최대 초당 한 번 기록합니다. 실패 시 대기 상태를 유지하고 Recorder/FFmpeg를 생성하지 않습니다.
4. 기본 로그 위치는 `F:\MyRecorder\Temp\display-diagnostics-<임의ID>.jsonl`입니다.
   설정에서 Temp를 바꾸었다면 해당 폴더에 생성합니다. 시작 오류 창에도 경로가 나옵니다.
   Temp 접근 실패 시 C드라이브나 개발 폴더로 자동 대체하지 않고 로그 저장 실패를 안내합니다.
5. `qt_screens`, `windows_monitors`, `selected_screen`, `selected_region`, `dpi`, `matching`,
   `physical_region`, `failed_condition`을 비교합니다. 실패 단계에 따라 이후 필드는 없을 수 있습니다.
   정상 매칭에는 `identity_and_geometry` 또는 `unique_geometry` 전략이 표시됩니다.
   `matching.geometry_checks`는 각 후보의 원점/배율 크기 검사를 기록합니다.

주요 오류 코드는 `NAME_GEOMETRY_CONFLICT`, `GEOMETRY_MATCH_NOT_UNIQUE`,
`QT_GEOMETRY_AMBIGUOUS`, `NATIVE_QUERY_FAILED`, `PER_MONITOR_DPI_REQUIRED`,
`SCREEN_LAYOUT_CHANGED`, `REGION_OUTSIDE_MONITOR`입니다. 이름이 같은데 좌표가 모순되는 경우에도
오류를 무시하지 않습니다. 실패 상세는 `validation`에, API 실패 원문은 `detail`에 기록합니다.
로그에는 실제 장치 정보와 로컬 경로가 있을 수 있습니다. 공개 저장소에는 올리지 않습니다.

## 기존 폴더에 안전하게 업데이트

1. 녹화를 끝내고 앱을 종료합니다. 기존 소스 폴더와 `settings.json`을 백업합니다.
2. https://github.com/Kipoong/MyRecorder → **Code → Download ZIP**을 내려받아 별도 폴더에서 풉니다.
3. `MyRecorder-main` 내부 파일/폴더를 기존 개발 폴더에 덮어씁니다.
   `.venv`, `bin`, 개인 `settings.json`은 삭제하지 않습니다. ZIP에는 개인 설정이 없습니다.
   `run.bat`과 `launcher.py`를 포함해 교체하고 소스 폴더가 한 단계 더 중첩되지 않게 합니다.
4. `install.bat` → `run.bat`을 실행합니다. 제목 표시줄 **V0.4.2**를 확인합니다.
   의존성 목록과 설정 스키마는 그대로이며 Python/FFmpeg 재설치는 필요하지 않습니다.
5. 기존 recordings/converted/temp 설정과 F드라이브 파일이 유지되는지 확인합니다.
   이전 EXE를 실행하면 소스 교체가 적용되지 않습니다. EXE 사용자는 `build.bat`으로 다시 빌드해야 합니다.

## Windows 실기 재검증표 — 전 항목 아직 미검증

| 조건 | 확인할 결과 |
|---|---|
| 현재 좌우 듀얼, 두 화면 100% | 진단에 Qt 2개/Windows 2개, 다른 원점, 실제 주 화면 플래그가 나타남 |
| 화면 목록 순서 | 이름과 좌표로 두 화면을 구별하고 Windows 표시 번호와 같은 순서라고 가정하지 않음 |
| 왼쪽 화면 전체 / 오른쪽 화면 전체 | 각각 10~30초 무음 녹화, 영상이 선택 화면과 일치, 1920×1080 MP4 재생 |
| 각 화면 내부 811×513 정도 영역 | 픽셀 크기/왼쪽 위 기준점이 영상과 일치. 코덱의 홀수 크기 짝수 패딩과 구분 |
| 초록 테두리 이동·8방향 확대/축소 | 같은 모니터 대응 유지, 가장자리 밖으로 나가지 않음, 시작 후 선택 위치 녹화 |
| 각 화면에서 시스템 소리 ON | 기존 WASAPI 출력 장치로 실제 재생음을 녹음, MP4 저장 및 A/V 싱크 |
| 녹화→일시정지→재개→저장 | 테두리 색/영역 고정, A/V 싱크와 영상 길이, 원본 보존 회귀 검사 |
| 주 화면을 오른쪽으로 변경 후 앱 재실행 | 왼쪽 모니터 음수 X에서도 정확한 화면과 영역 녹화 |
| 보조 화면을 위쪽으로 이동 후 재실행 | 음수 Y 원점에서도 정확한 변환 |
| 각 화면 125%, 150%; 100%+125%, 100%+150% | 앱 재실행, 실제 Qt DPR/Win32 물리 모드 로그 확인, 두 화면에서 전체·부분·테두리 위치 비교 |
| 앱 실행 중 해상도/배율/연결 변경 | 변경된 선택으로 시작하지 않고 재선택/재시작 안내 |
| 가로지르는 영역 또는 모순된 장치 정보 | 잘못된 영상 대신 명확한 실패 조건과 로그 위치 안내 |
| 테두리 영상 제외 | MP4에 선/조절점/크기 라벨이 들어가지 않음. 제외 실패 시 자동 숨김 |
| 30분 이상 및 가능한 1~3시간 | 음성 누락/드리프트/MP4 길이·용량·복구 상태 검사 |

임시 세션이 생긴 후 녹화 오류가 발생한 경우에는 기존 보존 정책을 유지합니다.
좌표 검증 단계의 실패는 아직 녹화 세션을 만들지 않은 상태입니다.
Windows 네이티브 API, DPI 경고 소멸, 실제 듀얼 화면 캡처와 오디오는 Linux 검사로 통과 판정하지 않습니다.
