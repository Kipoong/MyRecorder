# V0.4.3 연속 녹화와 모니터 간 영역 이동

## 사용 순서

1. 화면 목록에서 대상 화면을 고르고 **영역 드래그 선택** 또는 **선택 모니터 전체**를 누릅니다.
   녹색 테두리와 물리 픽셀 크기를 확인합니다. 화면 좌표 진단 기능도 유지합니다.
2. 대기 중에는 초록 이름표/테두리를 드래그하여 이동하고 8개 조절점으로 크기를 바꿉니다.
   다른 모니터로 이동하려면 이름표/테두리를 누른 채 포인터를 그 모니터로 옮깁니다.
   목적 화면을 다시 검증한 뒤 해당 화면 안으로 영역을 배치하고 화면 목록 선택도 함께 바꿉니다.
3. **녹화 시작** → 빨간 테두리, 영역 편집 잠금. 제목/경로/화면/오디오 설정도 잠깁니다.
4. **일시정지** → 주황 테두리와 **재개** 버튼. 종료와 달리 같은 세션의 새 구간을 이어 녹화합니다.
5. **종료 / MP4 저장** → 별도 **저장 중** 상태. 주황 테두리의 라벨도 저장 중으로 표시합니다.
   시작·일시정지·종료·영역 편집·제목 변경을 잠그고 창 닫기도 막습니다.
6. 저장 성공 → 즉시 녹색 대기 상태. 마지막 영역과 표시/숨기기 선택을 유지합니다.
   제목과 시작 버튼, 테두리 편집을 다시 사용할 수 있습니다. 같은 영역으로 바로 시작하거나
   다음 강의 제목/영역으로 바꿀 수 있습니다. 자동 초기화나 앱 재시작은 필요하지 않습니다.

테두리 표시를 끈 경우 상태 전환 중에도 숨김 선택을 유지합니다.
Windows 영상 제외 속성 확인이 실패하면 실제 캡처 동안 테두리를 숨기는 기존 정책을 유지합니다.
빨강/주황 표시가 필요해도 영상 제외를 확인하지 못한 경우에는 영상 보호가 우선입니다.
실제 gdigrab MP4에서 선·조절점·라벨이 제외되는지는 Windows 재검증 대상입니다.

## 모니터 이동 범위

- Windows 화면 번호나 목록 순서로 대응시키지 않습니다. V0.4.2의 식별자/좌표/DPR 검증을 유지합니다.
- 이동은 녹화 대기 중에만 가능합니다. 녹화·일시정지·저장 중에는 영역과 모니터를 고정합니다.
- 포인터가 목적 화면에 들어가면 영역 전체를 그 화면 안으로 제한합니다.
  두 화면 사이에 걸친 캡처는 지원하지 않습니다. 혼합 DPI의 화면 사이 빈 공간은 목적 화면이 아닙니다.
- 목적 화면의 논리 크기보다 영역이 크면 그 화면 안에 맞게 줄입니다. 모니터별 배율이 다른 경우
  논리 크기를 기준으로 이동하므로 물리 픽셀 크기가 바뀔 수 있습니다. 표시된 px 값을 확인하세요.
- 크기 조절은 현재 화면 안으로 제한합니다. 화면을 넘기려면 크기 조절점 대신 이름표/테두리를 이동합니다.
- 네이티브 드래그, 모니터 간 DPI 전환, HWND 재생성 시 영상 제외 유지 여부는 Windows 미검증입니다.

## 상태와 실패 처리

| 상태 | 테두리 | 시작 | 일시정지/재개 | 종료/저장 | 영역·제목 |
|---|---|---|---|---|---|
| 대기 | 초록 | 사전 점검 통과 시 | 비활성 | 비활성 | 편집 가능 |
| 장치 준비 | 빨강 또는 안전 숨김 | 비활성 | 비활성 | 비활성 | 잠금 |
| 녹화 | 빨강 또는 안전 숨김 | 비활성 | 일시정지 | 종료 / MP4 저장 | 잠금 |
| 일시정지 | 주황 | 비활성 | 재개 | 종료 / MP4 저장 | 잠금 |
| 저장 중 | 주황, 저장 중 라벨 | 비활성 | 비활성 | 저장 중, 비활성 | 잠금 |
| 저장 실패 | 주황, 저장 실패 라벨 | 비활성 | 비활성 | 저장 재시도 | 잠금 |

대기의 시작 조건은 유효한 모니터 내부 영역, 화면 대응 검증, FFmpeg/ffprobe 실행 파일 탐지,
진행 중 작업 없음, 이전 Recorder 소유권 없음입니다. 대기 중 약 1초 간격과 시작 직전에
화면 유효성을 다시 확인합니다. 실행 파일 탐지는 인코더/장치가 실제로 열릴 것이라는 보장은 아닙니다.
저장 폴더 접근과 WASAPI 장치 열기는 시작 시 다시 검사하며 실패하면 로그를 안내합니다.
FFmpeg가 실행 중 앱 밖에서 삭제되거나 새로 설치된 경우 앱을 재시작해 준비 검사를 다시 하세요.

저장에 실패하면 새 녹화를 시작하지 않고 **저장 재시도**를 제공합니다.
이전 세션의 MKV/WAV/진단 로그를 보존하며 MP4 성공을 보고하지 않습니다.
드라이버 또는 파일 쓰기 종료가 확인되지 않으면 자원 참조를 유지하고 새로운 캡처를 차단합니다.
자원 종료 실패가 계속되면 로그를 보존하여 원인을 확인해야 합니다. 실행 중 자원이 남은 상태의
창 닫기는 막습니다. 원본이 보존된 상태에서 종료를 재시도하세요.

정상 종료에서는 WASAPI 제어 스레드/PCM 쓰기 스레드 종료, 스트림 닫기와 PortAudio 해제를 확인합니다.
FFmpeg의 정상 종료 오류 시 제한 시간 내 강제 종료/회수를 시도하고 종료 확인 전 참조를 버리지 않습니다.
이미 끝난 FFmpeg의 stdin과 로그 핸들을 닫고 GUI 작업 QThread도 정리합니다.
영상 타임스탬프·오디오 샘플 처리·싱크 필터·기본 저장 경로와 설정 스키마는 바꾸지 않았습니다.
동명 파일은 기존 배타적 예약/번호 추가 로직으로 보관합니다. 기존 MP4를 덮어쓰지 않습니다.

## Linux에서 수행한 검사

- `python -m unittest discover -s tests -v`: **113개 통과**.
  기존 105개에 모니터 이동 3개, FFmpeg/오디오 종료 실패 보호 3개,
  모의 WASAPI 3회 자원 해제 1개, 실제 합성 MP4 3회 저장/음성/덮어쓰기 방지 1개 추가.
- `PYTHONPATH=. QT_QPA_PLATFORM=offscreen python tests/continuous_smoke.py`:
  합성 듀얼 화면을 번갈아 3회 녹화/저장, 같은 영역으로 4회째 시작, 일시정지/재개,
  저장 중 중복 클릭 차단, 실패 후 재저장, 경고창 이전 대기 복귀, 유효 영역/엔진 준비 조건 확인.
- 기존 GUI/overlay/display/OCR smoke와 compileall 확인.
- 실제 합성 MP4 세 파일의 A/V 스트림, 길이 차이, 디코딩, 앞선 파일 해시 보존 확인.
  GUI 시험의 캡처 엔진은 모의이며, 실제 미디어 시험은 FFmpeg 합성 입력입니다.
  오디오 자원 시험도 PortAudio 모의 객체이며 실제 WASAPI 드라이버 시험이 아닙니다.

## Windows 재검증 — 미검증

1. 두 화면 1920×1080, 100%에서 화면 좌표 진단을 각각 실행합니다.
2. 왼쪽 부분 영역 선택 → 시스템 소리 재생 → 15초 녹화 → 종료/저장합니다.
   저장 중 새 녹화/영역 변경이 막히고 완료 후 즉시 초록/편집 가능으로 바뀌는지 확인합니다.
3. 테두리를 오른쪽 화면으로 옮겨 다시 녹화/저장하고, 왼쪽으로 돌아와 세 번째 녹화를 합니다.
   앱 재시작 없이 같은 제목으로 진행하여 MP4 3개가 별도 생성되는지 확인합니다.
4. 영역을 다시 선택하지 않고 네 번째 녹화를 시작합니다. 제목 수정도 확인합니다.
5. 각 파일의 대상 화면/영역, 실제 시스템 소리, A/V 싱크, 재생 시간, F드라이브 경로를 확인합니다.
6. 일시정지 주황/재개 빨강, 녹화·일시정지 영역 잠금, 테두리 숨김 선택 유지를 확인합니다.
7. 최종 영상에 모든 색 테두리·조절점·크기 라벨이 없는지 확인합니다.
8. 저장 완료 후 이전 FFmpeg와 오디오 장치 점유가 남지 않는지 확인합니다.
9. 안전한 시험 폴더에서 저장 실패를 재현하고 원본 보존/오류 로그/저장 재시도를 확인합니다.
   실제 녹화 중 드라이브 분리나 원본 삭제로 시험하지 마세요.
10. 음수 원점과 100%+125%/150% 혼합 DPI에서도 대기 이동과 부분 영역을 확인합니다.
    추가로 가능한 30분 이상 연속 녹화와 1~3시간 장시간 오디오 검증을 수행합니다.

## 업데이트

앱 종료 후 개발 폴더와 개인 `settings.json`을 백업합니다.
GitHub **Code → Download ZIP**을 별도 폴더에서 풀고 내부 파일을 기존 폴더에 덮어씁니다.
기존 `.venv`, `bin`, 개인 `settings.json`과 F드라이브 자료는 유지합니다.
`install.bat` → `run.bat`을 실행하여 **V0.4.3**을 확인합니다.
의존성/설정 스키마 변경은 없습니다. EXE 사용자는 `build.bat`으로 다시 빌드해야 합니다.
