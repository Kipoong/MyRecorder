# V0.4 Windows 11 사용 설명 및 재검증 계획

## 기본 기능 승인 기록

사용자 보고에 따라 V0.3은 **화면 녹화 / 시스템 오디오 / F드라이브 MP4 저장** 세 가지의
Windows 11 기본 기능 테스트 통과로 기록했습니다. V0.4의 신규 기능과 장시간 싱크는 별개입니다.
실제 Windows에서 새로 확인하지 않은 사항은 아래 모두 '대기'입니다.

## 기존 개발 폴더에 안전하게 업데이트

1. 프로그램을 종료하고 기존 개발 폴더와 개인 `settings.json`을 백업합니다.
2. GitHub에서 최신 ZIP을 받아 **다른 임시 작업 폴더**에 압축 해제합니다.
3. ZIP의 `MyRecorder-main` 안 파일들을 기존 개발 폴더에 덮어씁니다.
   기존 폴더 자체를 삭제하지 말고 `.venv`, `bin`, 개인 `settings.json`, F드라이브 미디어를 유지하세요.
   `myrecorder\gui.py`가 패키지 폴더 안에, `run.bat`과 `windows.manifest`가 프로젝트 루트에 있어야 합니다.
4. `install.bat` → `run.bat`을 실행하고 V0.4 표시를 확인합니다. Python 의존성은 V0.3과 동일합니다.
   기본 경로와 개인 설정 스키마는 유지하며 마이그레이션/초기화하지 않습니다.
5. 예전 EXE는 소스 복사로 바뀌지 않습니다. EXE 사용자라면 `build.bat`으로 다시 빌드해야 합니다.
   V0.4 Windows EXE는 아직 개발자가 빌드/실행하지 않았습니다.
6. 업데이트 후 첫 시험은 기존에 통과한 100% 배율·동일 출력 장치·동일 영역에서 30초 녹화입니다.
   새 기능 사용 전에 이 기본 회귀 검사를 먼저 수행하세요.

일반 개발 위치 예시: `%USERPROFILE%\OneDrive\바탕 화면\allthetest\myrecorder`.
기본 F:\MyRecorder\Recordings / Converted / Temp와 폴더 선택·기억·접근 실패 시 차단은 유지합니다.

## 창 제목 인식

- 강의 브라우저의 해당 탭을 활성화한 후 앱으로 돌아와 **창 제목 → 직전 활성 창 → 제목 자동 인식**.
- 앱을 제외한 외부 활성 창은 대기 상태에서만 기억합니다. 빠른 창 전환으로 기억하지 못했거나
  다른 창을 선택하려면 **강의 창 목록 새로고침**으로 직접 선택합니다.
- Win32 창의 현재 제목을 매번 다시 읽으므로 선택 후 탭 제목이 변한 경우 새 제목을 읽습니다.
  최소화/닫힘/권한 등으로 읽지 못하면 기존 입력을 유지하고 수동 입력을 안내합니다.
- 브라우저/사이트 접미사까지 표시될 수 있습니다. 결과를 반드시 검토하고 수정하세요.
  비활성 브라우저 탭의 내부 내용·DOM·로그인 정보는 읽지 않습니다.
- 인식 텍스트는 공백/금지문자를 정리하고 길이를 제한합니다. 기존 파일 중복 번호 처리는 그대로입니다.

## OCR 설치 및 사용

OCR은 선택 기능입니다. 창 제목 방식과 기존 녹화는 OCR 설치 없이 동작합니다.
[Tesseract 설치 문서](https://tesseract-ocr.github.io/tessdoc/Installation.html)가 소개하는
Windows 배포처에서 Tesseract 5 x64와 `kor.traineddata`, `eng.traineddata`를 설치하세요.
Windows 설치 프로그램은 Tesseract 본체의 공식 배포물과 구분되는 별도 배포처의 빌드입니다.

필요하면 **OCR 엔진 선택**에서 설치한 `tesseract.exe`를 지정합니다. 경로 지정은 현재 실행 동안만
유지되며 일반 설치 위치/PATH에서도 찾습니다. Python OCR 패키지를 추가 설치하지 않습니다.
실행 파일만 옮기지 말고 DLL과 tessdata를 포함한 정상 설치를 사용하세요.

1. 모니터 선택 → **OCR 제목 영역 선택** → 제목 부분만 드래그합니다. Esc는 취소입니다.
2. 방식 **영역 OCR**, 언어 **한국어+영어**를 선택합니다. eng만 설치했다면 영어를 선택하세요.
3. **제목 자동 인식**을 누릅니다. 앱은 잠시 숨고 이미지 캡처 후 복귀합니다.
4. 결과가 강의 제목에 표시되면 검토·수정합니다. 빈 결과/실패는 기존 제목을 보존합니다.
5. 브라우저 이동·글자 크기·배율·모니터 구성이 바뀌면 영역을 다시 선택합니다.

OCR은 버튼을 누를 때만 실행하고 녹화/일시정지 상태에서는 버튼과 실행 경로를 막습니다.
PNG는 메모리로 전달하며 별도 이미지나 OCR 결과 텍스트 파일을 만들지 않습니다.
언어 조회는 10초, OCR 자체는 30초 제한입니다. 한국어 인식률은 글꼴·대비·모델에 따라 달라집니다.
화면 보호 기술을 우회하지 않으며 가려지거나 보호된 영역을 복원하지 않습니다.

## DPI 경고 원인 분석과 변경

V0.3은 QApplication 생성 전에 구형 `SetProcessDPIAware()`를 호출하고 Qt 자동 DPI 변수를 설정했습니다.
Qt 6은 기본적으로 Per-Monitor DPI Aware V2를 설정하므로 이미 정해진 프로세스 DPI와 충돌하면
Qt의 DPI 설정 실패 경고가 발생할 가능성이 있습니다. **실제 경고 전문을 받지 않았으므로
해당 경고의 원인을 확정한 것은 아닙니다.** Windows 호환성 재정의·앱 manifest도 영향을 줄 수 있습니다.

V0.4는 중복 호출/환경 변수 설정을 없애고 Qt 6에 맡깁니다. EXE에는 `windows.manifest`를 추가합니다.
Qt 화면 이름과 Win32 모니터 이름을 대응시키고 모니터별 원점·크기 비율로 영역을 변환합니다.
전체 가상 데스크톱 좌표를 단순히 배율로 곱하지 않으므로 왼쪽 음수 좌표와 혼합 배율도 계산할 수 있습니다.
다만 **계산 테스트 통과는 실제 Windows 좌표 통과가 아닙니다.** 매칭/인식 모드가 불명확하면
임의 좌표로 녹화하지 않고 경고합니다. 문제 시 검증된 기존 100% 환경으로 복귀하세요.

참고: [Qt 6 High DPI 문서](https://doc.qt.io/qt-6/highdpi.html).

### 배율별 실기 검증표 — 전 항목 대기

| 배율/구성 | 대상 | 확인 방법 | 판정 |
|---|---|---|---|
| 100% 단일 | 전체·드래그·OCR 영역 | V0.3 동일 조건 재녹화, 파일 크기·시각적 경계 확인 | 대기 |
| 125% 단일 | 전체·드래그·OCR 영역 | 논리 선택 → 물리 좌표 로그와 실제 픽셀·제목 일치 확인 | 대기 |
| 150% 단일 | 전체·드래그·OCR 영역 | 동일 방식, 화면 가장자리와 작은 영역 포함 | 대기 |
| 100%+125% | 보조 모니터·음수 원점 | 각 모니터 개별 선택, 잘못된 모니터/누락 영역 없는지 확인 | 대기 |
| 100%+150% | 보조 모니터·OCR | 좌우 배치 교환 후 앱 재시작·다시 선택 | 대기 |
| EXE 각 배율 | 동일 항목 | 새 manifest로 빌드한 EXE 별도 실행 | 대기 |

테스트 전 Windows 빌드, Python/PySide6/FFmpeg 버전, 실제 해상도·배율·모니터 배치를 로컬에 기록하세요.
그리드/눈금과 제목이 있는 화면을 준비해 선택 경계가 실제 영상에서 맞는지 확인합니다.
`recording-events.jsonl`의 `segment_begin.rect`는 FFmpeg에 전달한 물리 픽셀 (x,y,w,h)입니다.
출력의 영상 크기를 ffprobe로 확인하고 선택 영역과 시각적으로 비교하세요.
기존 인코더 패딩 때문에 물리 폭/높이가 홀수이면 출력은 해당 방향으로 1픽셀 커질 수 있습니다.

```bat
bin\ffprobe.exe -v error -select_streams v:0 -show_entries stream=width,height,duration -of default=noprint_wrappers=1 "F:\MyRecorder\Recordings\예시.mp4"
```

앱 실행 중 배율을 바꾸기보다 종료 → Windows 배율 변경 → 재실행 → 영역 재선택 순서로 시험하세요.
단위 테스트의 125/150% 예시는 수학적 변환 검증이며 실제 특정 모니터 측정값이 아닙니다.

## 제목 인식 테스트 — Windows 대기

1. 창 제목: 한국어 제목, 영어 제목, 여러 브라우저 창, 탭 변경 후 현재 제목 읽기.
2. 직전 활성 창: 브라우저 → 앱 전환; 실패 시 목록 직접 선택으로 대체 가능한지.
3. 선택 창 닫기: 실패 안내와 기존 제목 보존, 수동 수정 후 녹화 가능 여부.
4. OCR: 한국어/영어 혼합·작은 글자·빈 영역·엔진 누락·kor 누락·각 배율에서 수동 인식.
5. 제목 수정: 자동 인식 결과를 바꾼 뒤 해당 이름으로 MP4 저장되는지.
6. 금지문자/예약어/빈 입력: 저장 가능한 기본 이름 사용, 동일 제목 2회 저장 시 원본 덮어쓰기 없음.
7. 녹화 중: 인식·OCR·정리 버튼 비활성, OCR 프로세스가 새로 실행되지 않는지.

## 일시정지·시간·안정성 테스트 — Windows 대기

1. 영상과 소리의 동시 변화가 있는 시험 콘텐츠를 10초 녹화 → 10초 일시정지 → 10초 재개.
   저장 영상은 약 20초여야 하며 멈춘 동안의 내용은 포함되지 않아야 합니다.
2. 5회 이상 일시정지/재개. 각 구간 시작·끝의 입 모양/클랩·시각 패턴으로 오차를 측정합니다.
3. 30분, 이후 가능한 경우 1~3시간. 시작·중간·끝 오차를 기록합니다.
   목표는 절대 A/V 오차 200ms 이내와 시작 대비 변화 100ms 이내이며 아직 V0.4 달성 확인은 없습니다.
4. 녹화 중 시계는 추정값입니다. 일시정지 시 실제 구간 길이로, 저장 후 최종 영상 길이로 보정됩니다.
   시계는 초 단위 내림 표시이므로 ffprobe 소수 길이와 1초 미만 차이가 날 수 있습니다.
5. session.json의 각 `duration`, 최종 `output.video_duration`, `duration_difference`를 비교합니다.
   A/V 스트림 길이가 250ms 이상 다르면 경고하지만 길이가 같아도 실제 싱크는 다를 수 있습니다.
6. 시험용 쓰기 불가 폴더·장치 오류 등에서 원본 MKV/WAV·세션·오류 로그가 남는지 확인합니다.
   실제 중요 녹화나 운영 중인 드라이브에 고갈/손상 시험을 하지 마세요.

새 로그: `Temp\session-ID\recording-events.jsonl`에 구간 시작·좌표·구간 종료·저장 성공/실패 기록.
기존 `audio-diagnostics.jsonl`, 구간 FFmpeg 로그도 유지합니다.
일시정지/저장 실패 상태에서 창을 닫으면 원본을 보존하고 MP4 없이 종료할지 확인합니다.
저장 장치 손상이나 쓰기 실패에서 완전한 복구를 보장하는 것은 아닙니다. 실제 로그·제목·계정 경로는 Git에 올리지 않습니다.

## 완료 임시 세션 정리 테스트 — Windows 대기

- 녹화 종료 후 MP4를 재생하여 확인한 다음 **완료 세션 임시 파일 정리**를 누릅니다.
- 정상 완료 구간과 소유 표식, 최종 MP4 존재/크기/스트림 확인을 통과한 후보만 표시됩니다.
  삭제 확인 기본값은 '아니요'이며, 확인 후 다시 검사합니다.
- 실패 구간/저장 실패·출력 삭제/손상·이전 버전 불명 세션·정션/심볼릭 링크는 보존되어야 합니다.
- 정상 후보만 삭제되고 최종 MP4와 Recordings/Converted 및 다른 폴더는 남는지 확인합니다.
- 자동 정리 스케줄은 없고, 사용자가 정리를 요청하기 전까지 원본 세션은 그대로 보관합니다.
